# 試作の指示書（別の Claude Code セッション用）

使い方：ユーザーが、このファイルのURLか内容を別の Claude Code セッションに渡し、`/goal` に下の「完了条件」を入れて始める。

## 完了条件（`/goal` に入れる文）

```
/goal 「デモ動画を作る仕組み」の試作を、作業が終わるまで続けてください。最後に、(1)ツールごとの比較表（観点ごとに ○△× と一言）、(2)実測した時間・Claude Code の使用量・Gemini の費用、(3)推奨するツールとその理由、(4)「決まったこと」「まだ決まっていないこと」を、一覧で会話に出してください。表の本文も会話に出して。
```

## 目的と背景

個人でハッカソン（Built with Claude: Japan 2026）に出る。提出するデモ動画（3分以内）を、毎晩プレビューできる仕組みで作りたい。本番の作品とは別の場所で、仕組みを試す。

本番の仕様書は、公開リポジトリ https://github.com/Piyo-oyiP-GH/Ry-bwc-works の `idea/demo-video-pipeline.md`。**最初に読むこと。** 決まったこと、まだ決まっていないこと、確かめること、比較の観点が書いてある。

## 制約（最優先）

1. 本番のリポジトリ（Ry-bwc-works）には、何も書き込まない・push しない。作業は、新しい別のフォルダで行う。
2. API キーを表示・コピー・ログ出力しない。Gemini の API キーは、ユーザーが会話で伝えたファイルから、スクリプトの中でだけ読む（`AIza[0-9A-Za-z_\-]{35}` で取り出す）。確認で表示してよいのは「見つかったか」だけ。
3. 費用の上限：Gemini は ¥300（音声生成は1回数円の見込み）。超えそうなら止めて聞く。Claude Code の使用量は、`/usage` を試作の前後で見て、**週間の約5%を目安**にする（試行錯誤が多くなりそうなので、4%を超えた時点で一度止まって聞く）。終了時に、実際に使った量（前後の差）を必ず報告する。
4. 時間の上限：約2時間（配分の目安：素材45分（録画方法の比較15分を含む）、比較60分、まとめ15分）。超えそうなら、止めて聞く。**終わらなかった部分は「未確認」と書き、無理に終わらせない。**
5. インストールは、使うツール（Node.js 22以上、ffmpeg、Python、playwright、Hyperframes、Remotion、MoviePy）の公式の手順だけ。システム設定の変更、常駐ソフトの追加、アカウントの作成、パスワードの入力はしない。必要なら止めて聞く。
6. フォントは、ライセンスが明確なもの（例：Noto Sans JP、SIL OFL）を公式の配布元から入れる。BGM は使わない。
7. 使ったツールのライセンスを記録する。
8. 迷ったら、進める前に聞く。特に、費用・規約・時間。
9. 録画には、ダミーのデータだけを映す。API キー・メールアドレス・個人情報・設定画面が映らないようにし、書き出した後に目で確認する。

## 実行環境

ユーザーの Windows の PC 上の Claude Code で動かす想定。クラウドや別のOSで動いている場合は、最初にユーザーに伝え、「Windowsでの動かしやすさ」と書き出し時間は「未確認」と書く。

## やること（優先順位の順）

### 1. 素材（約45分）
1. 仮の絵コンテ（3シーン、各10秒前後）を作る。列：シーン／秒数／見せる画面（録画ファイル名）／日本語テロップ／英語テロップ（空欄でよい）／日本語ナレーション／読み（ひらがな。英単語・数字・固有名詞の読み間違いを防ぐ）。形式は、表の md と YAML のどちらがよいかを、使いながら見る。
2. 仮の素材として、簡単なサンプルの Web ページ（ToDo など。本番の作品とは無関係でよい）を作る。
3. Playwright でそのページの操作を自動化し、3本の短い画面録画を作る。設定を記録する。録画にテロップなどは焼き込まない。音声なし。次の点は、レビューで指摘された「記憶ベースの情報」なので、必ず確かめる（公式：https://playwright.dev/docs/videos ）：
   - 録画サイズは明示して指定する（指定しないと縮小される可能性がある）
   - 出力は WebM で、フレームレートを指定できない可能性がある → ffmpeg で一定の 30fps の mp4 に変換する
   - カーソルが映らない可能性がある → ページ側のスクリプトでカーソルを描く
   - 「毎回同じ映像」の判定：同じ操作を2回撮り、各クリップの長さの差が ±0.2秒以内であること（ファイルの完全一致は求めない）。録画用には固定のダミーデータを使う

4. 録画方法の比較（約15分）：Playwright 以外で、ターミナルなどを撮る方法として、ffmpeg（Windows の画面キャプチャ）と OBS を、同じ短い操作で撮って比べる。見る点：コマンドだけで開始・停止できるか（AIが操作できるか）／画質とコマ落ち／カーソルが映るか。

### 2. 比較（約60分）
同じ絵コンテと同じ録画3本から、テロップ付きの30秒動画が「1コマンドで」出るようにする。次の順に作り、**最初の1つを作ってから、次に進む**：
1. MoviePy（または ffmpeg）：基準にする
2. Hyperframes
3. Remotion：**1と2が終わって、時間が余ったときだけ**（導入だけで時間を使い切らないため。やらなかったら「未実施」と書く）

書き出し設定も記録する（目安：H.264・yuv420p・30fps固定、音声は48kHz、音量はおよそ -14 LUFS）。

各ツールで、次を確かめる：
- 「0:12のテロップを短く」「シーン3を2秒詰める」が、絵コンテの編集だけで反映されるか
- 日本語フォントが表示されるか。英語テロップを後から足せるか（日英2段）
- 書き出し時間、導入でつまずいた点
- ズーム・ハイライト・場面転換を、後から足せるか（時間があれば、1つだけ試す）

### 3. 合成音声と秒数（比較の最後。時間があれば）
決定済みのルールを試す：**音声を先に作り、その長さをシーンの秒数の基準にする。** 秒数＝音声の長さ＋前後の余白。ただし新しい画面には最低秒数を置く。初期値（仮）：前の余白 0.8秒、後の余白 0.5秒、新しい画面の最低 3秒。
1. 最初に、Google の公式ページで、使うモデル名（`gemini-3.8-flash-tts`）と料金が正しいかを確かめ（本番の仕様書の記述は、第三者の記事が出典で未確認）、TTS を**1行だけ**試す。
2. 絵コンテのナレーション（読みの列を使う）から音声を作り、選んだ1つのツールで、上のルールどおりに30秒動画を作る。
3. ユーザーに見てもらい、「画面を理解する時間が足りるか」を聞く。調整した値と、音声生成の費用を記録する。

### 4. まとめ（約15分）
作業フォルダに `RESULT.md` を作り、次を書く（会話にも出す）：
1. 比較表（ツール×観点。観点は本番の仕様書の「ツール比較の観点」7つ）
2. 実測：時間、Claude Code の使用量（前後の差）、Gemini の費用、軽い確認版（音声・演出なし、スクリプトで出す）とフル版（音声つき）の書き出し時間とトークンの違い
3. 推奨するツールと、その理由。データから言えることと、推測を分ける
4. 録画の自動化（Playwright）が使えるか
5. 決まったこと／まだ決まっていないこと
6. 本番の仕様書（`idea/demo-video-pipeline.md`）に反映してほしい点（ユーザーが後で反映する。あなたは書き込まない）

## 最後に

`RESULT.md` と、再現に必要なファイルは、作業フォルダに残す。本番のリポジトリには入れない。
