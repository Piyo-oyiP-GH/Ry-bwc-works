# デモ動画を作る仕組み（仕様 v1.1）

ステータス: 構想は確定（2026-11-03）。次は試作（今夜、別の Claude Code セッションで。指示書は `pilot-prompt.md`）

## ゴール

- **目標**：11/7 の1日で、質の高いデモ動画を仕上げられるようにする。そのために、開発の途中から、通しのプレビューを随時出す
- **この仕組みができた後にできること**：機能ができるたびに、録画と絵コンテの1行を足すだけで、いつでも、最初から最後までのプレビュー動画が出る。直したい所は「0:12のテロップを短く」「シーン3を2秒詰めて」のように、秒数かシーン番号で伝えれば反映される。最終日は、プレビューを手で仕上げるだけにする
- この段階では、動画の仕上がりに時間をかけすぎない

## 決まったこと

### 出力と層
1. 出すもの：**常に通しで見られるプレビュー動画**（頻度は項目15）。最終日の仕上げも、編集ソフトは使わず、プロンプトで絵コンテ・パラメータを直して再書き出しする
2. 3つの層。上の層は、下の層を変えない
   - **素材層**：画面録画。撮り方（解像度・フレームレート・音声なし）を固定し、テロップなどを焼き込まない
   - **ベース動画**：録画をつなぎ、テロップを乗せた短い動画。雰囲気は事前に考えてから作る。一発出しにしない
   - **品質向上層**：ベース動画の上に、別の層として重ねる
3. 作る順：絵コンテ → 音声 → 秒数の確定 → ベース動画 → 品質向上層
4. 品質向上層に足すもの（想定の順。根拠はない）：テロップのデザイン・場面転換 → ズーム・ハイライト → BGM
5. 雰囲気（テンポ・文字の量・色・見せ方）：過去動画の分析（`gallery-analysis.md`）の結果を見て、質問（インタビュー）で詳細まで詰めて決める。全体の動画ができる前から始める

### ナレーションと秒数
6. ナレーション：合成音声。**Gemini 3.8 Flash TTS**（`gemini-3.8-flash-tts`）を使う
7. **音声を先に作り、その長さをシーンの秒数の基準にする。** 理由：前回、Hyperframes で作った動画で、画面を人間が理解する時間を考慮できなかったため。秒数＝音声の長さ＋前後の余白。ただし、新しい画面には最低秒数を置く。余白と最低秒数の初期値は、試作で置いて、見て調整する
   - 既定（試作で確かめる）：絵コンテの列は「秒数（自動）」と「秒数（上書き）」。上書きに値があれば、そちらを使う（「シーン3を2秒詰めて」は上書きで反映する）
   - 既定（試作で確かめる）：録画が秒数より短ければ最後のコマで止め、長ければ末尾を切る。速度は変えない
   - 既定（試作で確かめる）：音声は、行ごとにファイルで保存し、文が変わった行だけ作り直す
8. 言語：日本語ナレーション＋日本語テロップ。英語テロップを後から足せるように、絵コンテに `telop_en` の列を最初から用意する

### 絵コンテ
9. **正本：リポジトリの `demo/storyboard.md`**（直すときに、ここだけを直す1つのファイル）。md は、アーティファクト以外の表示（README、台本、他のAI）にも流用できる。アーティファクトは、表示用のコピー。動画は生成物なので、直すのは常に `storyboard.md` だけ
10. 列：シーン／秒数／見せる画面／日本語テロップ／英語テロップ／ナレーション。修正は、秒数かシーン番号で指示する。「読み」の列は、試作で試す
11. 公開リポジトリなので、見せたくない内容は絵コンテに書かない

### 素材と録画
12. 機能ができるたびに、絵コンテに1行足して、画面録画を撮る
13. 録画・音声などの大きいファイルは、リポジトリに入れない（Drive またはローカル）
14. 録画の方法：Web の操作は Playwright。それ以外（ターミナルなど）は ffmpeg（Windows の画面キャプチャ）。OBS は使わない（AI が操作するには、パスワードの設定など人手が要るため）

### 書き出しと日程
15. 書き出し：2段階（軽い確認版＝録画をつなぎテロップだけ・スクリプトで出す／フル版＝音声・演出つき）を**暫定で採用**。頻度の粒度は、試作の実測（時間・使用量）を見て決める。「毎晩」とは決めない
16. 機能凍結：**11/7 18:00 に仮決定。11/8 に入ったら、機能の追加は禁止**（これは固定）。動画の作業は、凍結の後（11/7 18:00 〜 11/8 15:00 の提出目標）が中心になる
17. **常に通しの動画が出る状態を保ち、提出できる状態の動画を、常に1本保持する**：最初に全シーンを絵コンテに書き、録画が無いシーンは、仮のカード（テロップだけ）で埋める。品質が低くても、最初から最後まで1本になっている。新しい版は、別のファイル名で書き出し、通しで確認できてから差し替える
18. **提出は、11/8 が初めてにならないようにする**：初回の提出は、目標が11/6の夜、遅くとも凍結（11/7 18:00）までに行い、その後は、提出物を更新していく。提出後に変更できることは、確認済み。提出の記録は `demo/README.md` に書く
19. 11/8 の締め：12:00 に最後の書き出し、13:00 にアップロード開始、15:00 を提出の目標（締切は20:00）

### 試作
20. 別リポジトリ（作業用の別フォルダ）・別の Claude Code セッションで、今夜、最大約2時間
21. 完了条件：絵コンテ3シーン＋録画3本から、テロップ付き30秒動画が1コマンドで出る
22. 同じ絵コンテで複数のツールを比べる。Claude Code の使用量は**週間の約5%を目安**にし、ユーザーが `/usage` の前後の値を貼って、最終的な使用量を報告させる（表示の刻みは粗く、他のセッションの分も混ざるので、目安）

## レビューで出た論点（Opus の advisor。◎＝解消、○＝提案・未承認）

1. ◎ 層の設計の矛盾（音声を先に作ると秒数が変わる）：「音声を先に作り、秒数の基準にする」ことで解消（決まったこと7）
2. ◎ 手で仕上げ始めた後は、自動の作り直しをしない：編集ソフトは使わず、プロンプトで絵コンテ・パラメータを直して再書き出しする方針にしたので、手直しが消える問題は起きない
3. ○ 絵コンテに「読み（ひらがな）」の列を足す（英単語・数字・固有名詞の読み間違いを防ぐ）。試作で試す
4. ○ 審査員が英語話者なら、英語テロップは「後から」ではなく必須になる。試作で日英2段を必ず試し、Discord で審査員の言語を確認する
5. ○ 「毎回同じ映像」の基準：ファイルの完全一致は求めず、「クリップの長さの差が ±0.2秒以内」とする。録画用には固定のダミーデータを使い、本物の Claude が動く場面は別に撮る
6. ○ 録画に秘密が映る事故（URL・設定画面・開発者ツールに、API キーやメールアドレスが映る）：ダミーのデータを使い、書き出した後に目で確認する
7. ○ 書き出し設定（一般的な目安）：H.264・yuv420p・30fps固定・音声48kHz、音量はおよそ -14 LUFS
8. ◎ 試作の範囲：MoviePy（または ffmpeg）と Hyperframes を必ず、Remotion は時間が余ったときだけ。実行環境は Windows の PC と明記した
9. ○ 日程：YouTube は高画質版の処理に時間がかかる。advisor は機能凍結を11/6夜にするほうが安全と指摘（11/7 18:00 に仮決定したので、この点は残る）

## 最初の試作で確かめること

1. 同じ絵コンテと録画で、ツールごとに「1コマンドで30秒動画が出る」か
2. 秒数・シーン番号の修正が、絵コンテの編集だけで反映されるか
3. 日本語フォントの表示、日英2段のテロップ
4. 書き出し時間、導入でつまずいた点
5. ズーム・ハイライト・場面転換を、後から足せるか
6. 「音声の長さ＋余白、新しい画面は最低秒数」のルールで、画面を理解できる長さになるか（あなたが見て確認し、調整した値を記録する）
7. Playwright で録画を自動化できるか（録画サイズの指定、30fpsへの変換、カーソルの描画。同じ操作を2回撮って、クリップの長さの差が ±0.2秒以内か）
8. Claude Code の使用量（ユーザーが貼った /usage の前後の値の差。目安）と、Gemini TTS の費用（応答の使用量から）。軽い確認版とフル版の、書き出し時間の違い。測る単位は「修正1回＋書き出し1回」
9. 録画方法：ffmpeg（Windows の画面キャプチャ）で、コマンドだけで開始・停止できるか／画質とコマ落ち／カーソルが映るか
10. 録画が無いシーンを、仮のカード（テロップだけ）で埋めても、1本の動画が出るか（常に通しで見られる状態を保つため）

## ツール比較の観点

1. AI操作性（1コマンドで再現できる、人の操作が要らない、エラーが分かりやすい）
2. 修正のしやすさ（秒数・シーン番号の修正が、絵コンテの編集だけで反映される）
3. 日本語（フォントの表示、日英2段）
4. 書き出し時間と、Windows PC での動かしやすさ
5. 後から足せる演出の幅
6. ライセンス（今回のハッカソンで使えるか）
7. 音声の長さに合わせて、秒数を決められるか
