# 過去作品のデモ動画分析

ステータス: **やりたい**。中身は検討中

## 目的

過去の Claude ハッカソンの作品ギャラリーで、最終選考に残った動画と残らなかった動画を Claude に比べさせ、評価されやすい動画の傾向をつかむ。

## 対象

- 過去回のギャラリー（全体で約280〜500件、各3分以内）
- 最終選考に残った動画すべて
- 比較用として、残らなかった動画から約20本（同じ回のハッカソンから選ぶ）

## 進め方（案）

1. 評価項目を先に決めて固定する（定量的に比べるため）
   - 例：動く画面が出るまでの秒数、実演の時間の割合、冒頭で課題を提示しているか、ナレーションの有無、テロップの量、困りごとを人物で語っているか、尺
2. 動画を、文字起こし（音声）と場面ごとの静止画（1本あたり15〜20枚）に変換する。Claude は動画を直接見られないため
3. まず1本で試し、トークン数と処理時間を測る
4. 最終選考の動画をすべて分析する。1本ごとに評価項目を CSV の1行に出力する
5. 比較用の約20本を同様に分析する
6. 最終選考とそれ以外の差を集計する

## 動画が見られなくなっている場合

YouTube の掲載が終わり、開けなくなった動画がある（最終選考・その他の両方）。

- 動画がまだ残っているほかのサイトを検索して収集する
- 見つからなければ「なし」として記録し、分析対象から外す
- どこから取得したかを記録する

## 注意点

- 本数が少ないため、統計的な有意差までは出ない。傾向をつかむ目的と割り切る
- 動画のダウンロードはクラウド環境からは難しいため、PC の Claude Code で実行する想定
- 本筋ではないので時間を区切る（案：最大2〜3時間）

## 確定したこと（2026-11-03）

- ギャラリー
  - Opus 4.6回: https://cerebralvalley.ai/e/claude-code-hackathon/hackathon/gallery （全227件、最終選考8件）
  - Opus 4.7回: https://cerebralvalley.ai/e/built-with-4-7-hackathon/hackathon/gallery （全288件、最終選考9件）
  - 最終選考は「Finalists」タブで分かれている。動画は YouTube 以外に Loom、Google ドライブ、OneDrive、FlexClip も混在
- 最終選考の動画をすべて分析する。見られない動画は、ほかのサイトを探し、それでも見られなければ対象外にする
- 比較用は、最終選考外から回ごとに約20本。回ごとに分けて分析する
- 目的は傾向をつかむこと（統計的な結論は出さない）
- 採点の物差しは今回の審査基準（strategy/judging-criteria.md）
- 動画のスタイルを読み取り、デモ動画の作成ツール選びの材料にする。おすすめの OSS と利用規約（今回のハッカソンで使えるか。不明なら不明と示す）を報告する
- トークン予算は週間利用制限の5%まで。最初に1本だけ試して消費を測る
- 分析設計は別モデル（Opus）に監査させる
- ダウンロードした動画は公開しない。残すのは分析結果のみ

## 方式の確定（2026-11-03）

- 動画のダウンロードや画像の保存はしない。YouTube の URL を Gemini API に直接渡して観察する（公開動画のみ対象）
- 対象は57本：最終選考17（4.6回8＋4.7回9）＋比較用40（各回20、YouTube リンクのある最終選考以外から乱数で抽出）。YouTube 以外の動画とリンクのない作品は母集団から外れる
- 観察シートは30項目（今回の審査基準4軸＋制作面）。設計の理由と根拠は Google ドライブの `bwc-video-analysis` フォルダ内の `rubric.md`
- 予算は既定 ¥1,500、上限 ¥3,000。最初に3本で実測してから本番
- 実行は別の Claude Code に任せる。引き継ぎ資料と実行プロンプトは同じドライブのフォルダにある
- 結果と手順はドライブに置く。このリポジトリには、あなた自身の結論だけを書く
